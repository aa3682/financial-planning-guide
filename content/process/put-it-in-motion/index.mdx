# Put it in motion

Putting the plan in motion is the sixth step of the planning process, the one planners call [implementation](/glossary#implementation). You take the plan everyone signed off on in [Review together](/process/review-together) and carry it out until what exists matches the page. Every step so far produced a document. This one produces change.

## Why it matters

A plan that is agreed but not carried out is a wish with a date on it. Nothing in the earlier steps moves any money. This step does.

Momentum is the scarce resource. At sign-off the plan feels real and everyone remembers why. That fades within weeks. Finish the first task within days of sign-off, even a small one. A plan with one task done is a plan someone is following.

The greater danger is the plan that stops halfway. Half done can mean money in transit that nobody is watching, or an old policy cancelled before the new one is in force. A plan not started at least leaves the old arrangements intact.

## What actually happens

### Turning instructions into dated tasks

Each block of the plan becomes one or more tasks, each with a name and a date: open the account, by this date, by this person; then set up the transfer. Work through the blocks in the [funding order](/glossary#funding-order), the sequence the goals were ranked in, so that if you stall, the goals that matter most are done.

Most plans call for the same few kinds of action: opening an account, or [retitling](/glossary#retitling) one, which means changing whose name is on it; setting up an [automatic transfer](/glossary#automatic-transfer), a standing instruction that moves a set amount on a set day; updating who is named as [beneficiary](/glossary#beneficiary); adding coverage, then dropping it, in that order; signing documents; and paying down or restructuring debt. The choice of product for each job was made in [Weigh the options](/process/weigh-the-options).

### Starting the slow tasks first

Some tasks take an afternoon. Others take weeks because other people are involved: an application to be approved, a transfer between institutions to clear, a legal document to be drafted and witnessed. Start those first, so the waiting runs alongside the quick work. A slow task started late is the usual reason a plan is still half done at the next review.

### Automating what can be automated

Anything that happens every month should happen without anyone remembering. A transfer that depends on memory stops the first busy month. Wherever the plan repeats, set it up as an automatic transfer or payment, so the plan runs on the calendar [instead of on willpower](/domains/money-and-behavior).

### Keeping a done list

Keep one simple list beside the plan: every task and its state, not started, waiting on someone, or done, with the date. Check it against the plan, block by block. You bring this list to [Stay on course](/process/stay-on-course), where the first question is whether the plan happened at all.

### When a task shows the plan was wrong

Sometimes an instruction cannot be carried out as written: the account has a rule the plan did not know about. A small mismatch, one that changes how but not what, gets fixed on the spot and noted on the done list. A large one, which changes how much, which route, or whether the goal still adds up, goes back to [Build the plan](/process/build-the-plan). Do not write a new plan at the counter.

## Questions to ask yourself

- Which task can I finish this week, and which must I start this week?
- Which tasks depend on someone else, and have I started them?
- What still depends on me remembering?
- Is any money in transit, or any coverage cancelled before its replacement is in force?

## Common mistakes

- **Waiting for a clear week.** There is no clear week, and the plan ages while you wait.
- **Doing the easy tasks first.** Quick wins feel like progress while the slow applications sit unstarted.
- **Cancelling before replacing.** Closing the old account or policy before the new one is in force creates the gap the plan was meant to close.
- **Rebuilding the plan at the counter.** A form that does not fit the plan is a reason to size the mismatch, not to decide something new.

## For advisors

<Callout type="info">
At this step you are executing, and the client should always know what is done, what is waiting, and on whom. Build a task list with an owner and a target date for each item, in the client's funding order, and start the items that involve third parties first. Document each action as it completes: the date, the confirmation, the account or policy as it now reads, and anywhere the plan could not be carried out as written and what was done instead.
</Callout>
